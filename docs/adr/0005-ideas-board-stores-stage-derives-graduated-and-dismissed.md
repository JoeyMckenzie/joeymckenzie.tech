# The ideas board stores stage but derives graduated and dismissed

The admin has a personal **Ideas** board: a single-operator Kanban of blog ideas that ripen through lanes — **Spark → Developing → Ready** — and graduate into real `Post` drafts. It is strictly separate from the `.backlog/` engineering tasks and is blog-ideas-only; general/side-project todos are deliberately excluded until real usage proves the need.

`ideas.stage` is a stored `IdeaStage` enum, which is the one place this feature keeps an explicit status column. The rule everywhere else in this app is *never store what you can derive* — `posts.published_at` is the single source of truth for `PostStatus`, not a status column (ADR 0001 grain). Stage does not break that rule: "Developing" is a human judgment about ripeness that no timestamp can derive, so it must be stored. The two terminal outcomes stay derived and are **exits off the board, not lanes you drag into**: `post_id` set = **Graduated**, `completed_at` set = **Dismissed**. On-board is both-null, arranged by `stage`.

Graduation reuses the post-authoring pipeline rather than fabricating a record. A valid `Post` requires `tag_id`, `description`, a non-nullable `image`, `content`, and a unique `slug` — an idea has a title and scratch notes and none of that. So the **→ Draft** action deep-links to `posts/create?from_idea={id}`, seeding `title` and `content` from the idea; `PostController@store` writes `idea.post_id` back on save. This means "Graduated" is truthful (a real draft exists), writes zero new post-creation code, and — via `nullOnDelete` on `post_id` — an abandoned draft returns its idea to the board instead of orphaning it.

Rejected: a **fully-derived status** (nothing can derive "Developing"); a **lane per terminal state** (graduating needs the create form, and dismissed is not a drag target, so those "lanes" would be lies or special cases); and **auto-creating a bare `Post` draft** on graduation (the non-nullable `image` plus required `description`/`tag_id` would force placeholder junk into the posts list). Notes are a plain textarea, not the CodeMirror editor — they are raw capture that becomes `content` in the create form, where the real editor already lives (ADR 0004). This is recorded so the board is not later "upgraded" into a general task manager or given a stored status for the terminal states.
