# MySQL is the source of truth for posts

The previous site used Orbit, where markdown files in `content/posts/` were the source of truth and the database was a derived cache. This site persists posts (and their views and reactions) in MySQL, and MySQL is authoritative. The existing markdown files are imported **once** as a backfill (keyed on the post's unique `slug`); deploys do **not** re-import them, so future admin edits are never overwritten by repo files. Orbit's `storage_key` file-identity field is dropped — `slug` is now the unique natural key and the DB row `id` is the stable key for foreign keys. The trade-off: post content is no longer git-versioned, which we accept because DB-backed authoring (a WYSIWYG admin) and per-post analytics (views, reactions) both require the database to own the content.
